## Safe local setup and supported composition

`documents.pilot.SupervisedPilot` is a trusted local Python facade, with no listener, upload endpoint, participant credentials, identity issuer or provider factory. An authenticated operator supplies an existing verified `Principal` through the supported OIDC boundary. Disabled/static bearer mode is insufficient to construct that principal. Participants see only the bounded inert local presentation, with the operator retaining keyboard, terminal, host, credentials, stores and publication privileges. The existing OIDC restrictions on legacy Streamlit/query routes remain intact.

Construct it with the actual existing `SecurityAuthority`, `GovernanceLedger`, shared `SQLiteInferenceAdmission`, object store, durable job ledger, publication service, explicit managed settings, separate explicit Q&A capability, planning profile and approved source records. Use one private control database for the entire pilot. Reopening binds exact authority/storage paths, quota key/policy, catalog, models, source approvals, v11 settings and profiles. Never clone/reset financial authorities or replace them to make preflight pass. All quota consumers must run the updated admission implementation before using its exclusive-call option; older running code cannot enforce the new exclusivity marker.

Use the existing project Python environment; install no new runtime or service for this reference. The supported entry point for composition is the Python constructor, not a production CLI. An authorized composition supplies these exact constructor arguments:

| Argument / prerequisite | Existing interface and binding |
| --- | --- |
| `authority` | `security.authority.SecurityAuthority`, registered verified operator with `Action.PUBLICATION_MANAGE` and the selected owning scope |
| `objects`, `jobs` | `documents.storage.LocalObjectStore`, `documents.jobs.sqlite.SQLiteJobLedger` configured through `JobSettings(database_path=...)`; retain source, plan, job/fence and checkpoint identities |
| `governance`, `admission` | Existing `GovernanceLedger`, `SQLiteInferenceAdmission`; same owner/tenant policy/catalog, shared quota key/history and exact authority files used by every consumer |
| `publication` | `PublicationService` with `SQLitePublicationAuthority`, the same objects/jobs/scope, approved vector port and `RetrievalEncoder`; initialize/load local retrieval under operator control |
| `provider` | Existing provider-neutral structured provider with pinned general/summarization models; no provider factory is created by the pilot |
| `managed_settings`, `analysis_capability`, `planning_profile` | Explicit `ManagedSettings`, separate Q&A `CapabilityProfile` and bounded `DigestionProfile`; every managed `StageProfile.template_version` is `managed-prompt/11` |
| `control_path`, `sources`, `policy` | Private pilot SQLite control file, validated `SourceApproval` sequence and optional downward-bounded `PilotPolicy`; there is no `PILOT_*` environment schema |
| Optional controls | `execution_permission`, `clock`, `extraction_limits`, `reranker`, `initialize`; production authorization cannot be replaced by fixture helpers |

Keep private SQLite/object/vector directories under operator control; do not put authorities, source packets, keys or participant metadata in Git. Review the existing [OIDC/governance configuration](../security/phase_17g.md#required-governance-configuration) and [Entra profile](../security/entra_v2.md) rather than inventing allowances. Runtime settings include `API_AUTH_MODE=oidc_jwt`, `GOVERNANCE_ENABLED=true`, `OIDC_CONFIGURATION`, `SECURITY_AUTHORITY_PATH`, `GOVERNANCE_AUTHORITY_PATH`, `GOVERNANCE_PROVIDER_PATH`, `GOVERNANCE_PROVIDER_KEY`, `GOVERNANCE_POLICY`, `GOVERNANCE_PRICING` and `GOVERNANCE_PROVIDER_POLICY`. In OIDC mode `API_AUTH_TOKEN` must be absent. Provider configuration remains at the existing inference boundary (`INFERENCE_PROVIDER` and its existing adapter settings); managed configuration uses `DOCUMENT_INFERENCE_` via `ManagedSettings`. Supplying these settings is not permission to contact a provider. Stage 3 operates no services and reads no real authority or credentials.

The [offline composition example](../../tests/pilot_helpers.py) demonstrates constructor wiring only: its `_verified_principal`, policies, prices, HTTP responses, embeddings and reranker are synthetic test fixtures and must not establish real identity or spending authority. Future real-provider use requires its own reviewed integration of the permission hook and independent signing procedure before any call. No production live launcher is supplied by this facade.

First-time creation of a new pilot control database requires explicit `initialize=True`. Normal startup uses the default `False` and requires an already initialized, bound authority. Missing or empty control storage fails closed, including requests on a live instance; it is not a new pilot. Restore the approved consistent authority after an outage. Never use first-time initialization to replace lost revocations or reuse existing session approvals. Initialization against an existing file is refused.

Select `managed-prompt/11` in **every** stage profile; the global default remains v10. The runner rejects implicit v10, model substitution, foreign scope, unknown source approvals, personal/private classifications and erasure-required documents. It only accepts bytes of an approved source; there is no participant-controlled filename, URL fetch or filesystem path argument. A rights reference/approved hash is an operator record, not an inference from public availability. Native-text screening also needs operator inspection for essential tables, columns, formulas or graphics that native extraction cannot reliably classify.

`PilotPolicy` defaults and hard ceilings are `max_sessions=3`, `max_source_bytes=1_000_000`, `max_pages=4`, `max_characters=4000`, `max_synthesis_calls=3`, `max_questions=3`, `max_input=24800`, `max_output=3000`, `workflow_seconds=600` and `provider_seconds=60`. They can be tightened. One session/document job may be open; at most six provider attempts per document are allowed, with no retry/fallback (`RetryPolicy.max_attempts=1`). Pilot requests acquire `SQLiteInferenceAdmission.acquire(..., exclusive=True)`, enforcing one exclusive admitted provider request within the supported shared authority. Unrelated upstream consumers and older running binaries remain outside that proof. `session_seconds` defaults to 3,600 (valid range 1–86,400); each approved session must fit that configured duration and its approval/source/principal expiry. `audit_limit` defaults to 10,000 (maximum 100,000). These are local policy fields, not new global application limits. Existing extraction, model, context, child and publication constraints can refuse smaller inputs. The execution deadline covers synthesis and Q&A together. Initial financial preflight forecasts the full remaining six-call envelope against the existing owner/tenant history and current catalog; runtime reservation/admission still decides each call. The forecast does not promise capacity or authorize spending.

Native PDF parsing uses `IsolatedPdfRunner` and `ParserBounds`: default wall time 10 seconds, CPU 5 seconds, address space 512 MiB, output 256,000 bytes, file-size backstop 2 MiB, at most 32 open descriptors and no core dump. Bounds accepted by `ParserBounds` are wall >0–30 seconds, CPU 1–20 seconds, address space 32 MiB–1 GiB, and `1024 <= output_bytes <= disk_bytes <= 4 MiB`. The existing extraction settings may tighten eligibility further; intake also caps `max_blocks` at 4,000. Python writes/process launch/socket side effects are denied in the POSIX child; diagnostics are discarded and failures sanitized. The parent reaps it and normally removes its private temporary directory. This is resource containment, not a syscall/container sandbox for compromised native code. Size alone does not approve a source; scans, essential graphics, complex layouts, personal/private data and erasure-required sources remain ineligible.

`fixture_execution_only` is the default and requires an explicitly marked deterministic provider and synthetic session. It refuses external-mode inference. A future real-provider composition must supply a separately reviewed execution-permission hook enforcing its exact independent authorization **on every call**, before reservation and again before execution. No live approval verifier/launcher, credential acquisition or signing is added or invoked by this task. This facade does not replace the existing independent signing procedure. Do not attach a real provider to a fixture composition.

## Operator sequence

1. Validate immutable `SourceApproval` and `SessionApproval` records. `create_session(operator, record)` distinguishes operator authentication, session approval and document approval from local execution authorization. A synthetic fixture has `consent=synthetic_fixture` and no consent timestamp. A real external record requires actual consent timestamp, notice, rights/provider/retention decisions and separate privacy, quality and exposure references. Draft templates are invalid until completed/approved; code does not obtain or legally approve consent.
2. `select_source(operator, session_id, approved_bytes)` verifies hash/rights/type/bounds, runs isolated native parsing, records immutable write intents, builds a bounded managed plan and renders leaves before execution. It refuses images/graphics/failed extraction; it does not silently omit units. Interrupted intake requires inspection/closure, not automatic replay.
3. `start(operator, session_id)` performs worst-case financial/provider preflight and idempotent durable admission with attempt limit one. `step(operator, session_id)` performs one durable step through the existing worker, fencing, managed inference, shared admission, governance and G1/G2/receipt contracts. Observe `status`. Rate denial/failure is terminal for this bounded run; do not loop retries or create another session to bypass it. Repeat `start` only resumes the same admitted job. Never pass raw queue/store access to a participant.

   Alternatively, `associate_retained(operator, session_id, accepted_job_id)` requires an explicitly approved `retained_digest_sha256` in the source record. It independently reconstructs the unchanged accepted v11 source/result/receipt graph, rechecks the pilot bounds and binds that exact output without regeneration. It grants no new execution/Q&A allowance. Historical financial/provider observations remain in the inventory. Do not approve another participant's private answers for reuse; only explicitly approved nonpersonal source results belong in this path.
4. `publish(operator, session_id)` requires accepted COMPLETE coverage, prepares and activates through `AuthorizedPublication`, records the generation **and epoch**, and explicitly loads its replica. After restart call `load_presentation` as a controlled operator load; serving does not rebuild BM25. Old/ABA generations, revoked authority and missing inventory deny release.
5. `review_packet` returns protected source/digest bindings with empty human-review fields. `attach_review` records separately completed findings against exact evidence hashes and distinct reviewer codes; it does not establish that an asserted reviewer is qualified/independent. Operator/domain reviewer verification remains mandatory. No historical human-review register is changed.
6. `present(operator, session_id, sink)` sends only the accepted digest, executive synthesis, coverage/limitations, canonical evidence and page/text-span citations. Use a bounded, synchronous, non-reentrant local sink that writes the result of `documents.pilot.presentation.render_text(packet)` to the controlled local display; do not render supplied HTML/Markdown or expose raw stores. Source and model text remain untrusted data. Final session, security and publication locks guard actual handoff. Delivered content cannot be recalled.
7. `question(operator, session_id, question, sink)` derives the selected document server-side and caps questions including abstentions/failures. It uses `AuthorizedAnalysis` and the same existing ledgers. Synthetic answers are labeled fixtures. In external mode, newly generated answers are held privately with `EXPERT_REVIEW_REQUIRED`; `answer_review_packet`, two exact-output reviews and `present_answer` are required before participant release. Digest reviews never authorize a later answer. Insufficient evidence is an explicit abstention; structural citation validity remains distinct from semantic entailment.
8. `feedback` accepts only structured rating/repeat/notice-understood/issue fields. No free-text analytics or names are accepted. `close(..., withdrawal=True)` immediately closes the presentation authority, fences eligible jobs and generates an inventory. Normal `close` also revokes presentation access. Shared source artifacts and historical publication generations are retained.

## Stop, recovery and retention

`stop(operator)` durably denies pilot intake, governed provider admission and presentations before best-effort scoped cancellation. It remains durable when pilot audit capacity is full. An in-flight provider call can complete and bill. Known usage stays settled; absent/partial usage stays UNKNOWN, with its existing financial obligation. No refund is inferred.

Crash-active/UNKNOWN operational intents block further pilot calls across reopen. First stop/quiesce all relevant workers. Reconcile provider and financial authorities using independently trusted usage evidence and their existing ports; preserve original obligations/history. `reconcile_operation(..., quiescence_reference=...)` only observes terminal financial/provider state and records operational reconciliation; it never settles/releases money. `reopen_intake` cannot reopen a stopped/closed participant session, replay an attempt or erase an uncertain intent. A crashed attempt without sufficient reconciliation evidence remains blocked. Dedicated job-ledger reconciliation can be invoked by its trusted existing operator procedure; no autonomous recovery SLA is claimed.

Restore only a consistent authorized backup containing all acknowledged revocations, usage and epochs, with workers quiesced. Never restore an older authority snapshot after later admissions; that loses obligations. Tests cover post-stop consistent SQLite snapshots and object unavailability/restoration, not arbitrary stale-backup rollback or hostile administrators.

`inventory` accounts for all 19 lifecycle classes, immutable write intents including orphans, accepted references, publication generations, vectors, per-call usage and operational intents. It reports actual presence versus unknown/unverified state; sparse/process/scratch copies, backups and upstream retention have explicit residuals. The operator must supply/accept actual private storage locations, custodians and approved class-specific deadlines; the generic private-authority labels are not an operated backup inventory. No physical erasure is certified. `PURGE_PENDING` is preserved and erasure-required data classes are refused.

Participant codes, consent metadata, review findings and structured feedback are private, outside Git. After the approved metadata retention deadline, `retire_metadata` logically redacts session metadata and removes feedback/review/held-answer rows. SQLite freelists, backups and other copies remain unverified, so this still reports `PURGE_PENDING`. There is no automatic timer or finite physical-erasure promise. Clear any operator display/export under its approved private handling procedure and record its outcome separately.
